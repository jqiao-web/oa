### 1、基础分布式锁（自动续期）
```
线程请求加锁
    │
    ▼
tryLock(最多等 5 秒)
    │
    ├── 5 秒内获得锁 ──► 执行业务 ──► finally 释放锁 ──► 返回结果
    │                      │
    │                 看门狗每 10 秒续期一次
    │                 (默认锁 30s，续到 30s)
    │
    └── 5 秒未获得 ──► 抛 RuntimeException
```
> 看门狗续期原理
> 只要持有锁的线程还活着，看门狗就会不断续期。如果线程挂了（JVM 崩溃），看门狗停止工作，锁在 30 秒后自动过期，不会死锁。
```
时间线 ──────────────────────────────────────────────►

t=0s    获得锁（默认 TTL = 30 秒）
t=10s   🐕 看门狗续期 → TTL 重置为 30 秒
t=20s   🐕 看门狗续期 → TTL 重置为 30 秒
t=25s   业务执行完毕 → 手动 unlock()
t=30s   （锁已被手动释放，看门狗停止续期）
```

### 2、带超时的分布式锁（不自动续期）
```
基础锁（自动续期）：
lock.tryLock(5, TimeUnit.SECONDS)
→ leaseTime = -1（Redisson 内部值）→ 启动看门狗 → 自动续期

超时锁（不续期）：
lock.tryLock(5, 10, TimeUnit.SECONDS)
→ leaseTime = 10 → 不启动看门狗 → 10 秒后强制过期释放
```

### 3、公平锁

```
非公平锁（基础锁）：
线程 A 释放锁 ──► 线程 B/C/D 同时竞争 ──► 谁抢到算谁（可能 D 先抢到）

公平锁：
线程 A 释放锁 ──► 按排队顺序 ──► B 先获得 ──► B 释放 ──► C 获得 ──► D 获得
                                  (先到先得，FIFO)
```
